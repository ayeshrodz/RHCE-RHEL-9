<Lead>
One playbook, three plays: web servers that publish a page built from their own facts, a user for each environment created only where it belongs, and a final play that checks every page from the control node. Solutions are hidden under each task. Try each one yourself first.
</Lead>

This lab covers chapters 2 to 5: multiple plays, variables and facts, loops, conditions, handlers and templates. The project `~/review-playbooks` has an `ansible.cfg` and the review `inventory` (`dev`, `test`, `prod`, and `webservers` containing `prod`). Put all three plays in `site.yml`.

  <Task title="The web server">
    Start `site.yml` with a play for `webservers` that:

    - installs `httpd` and `firewalld`,
    - starts both services and enables them at boot,
    - opens the `http` service in the firewall, now and permanently.

    <Reveal title="Show solution">

```yaml title="site.yml"
---
- name: Web servers publish a page
  hosts: webservers
  tasks:
    - name: Web packages are installed
      ansible.builtin.dnf:
        name:
          - httpd
          - firewalld
        state: present

    - name: Services are running
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
        enabled: true
      loop:
        - firewalld
        - httpd

    - name: http is allowed
      ansible.posix.firewalld:
        service: http
        permanent: true
        immediate: true
        state: enabled
```

    `dnf` takes a list of packages in one task, which is faster than a loop. `service` takes one name at a time, so it loops.
    </Reveal>
  </Task>

  <Task title="Settings from a template, restart only on change">
    Add a play variable `web_admin` with the value `webmaster@example.com`. Create `templates/site.conf.j2` that produces this file, and deploy it as `/etc/httpd/conf.d/site.conf`, mode `0644`:

```text title="/etc/httpd/conf.d/site.conf"
# Ansible managed
ServerAdmin webmaster@example.com
```

    `httpd` must restart when, and only when, this file changes.

    <Reveal title="Show solution">

```jinja title="templates/site.conf.j2"
# {{ ansible_managed }}
ServerAdmin {{ web_admin }}
```

```yaml
- name: Web servers publish a page
  hosts: webservers
  vars:
    web_admin: webmaster@example.com
  tasks:
    # ...the three tasks above...

    - name: Site settings are in place
      ansible.builtin.template:
        src: templates/site.conf.j2
        dest: /etc/httpd/conf.d/site.conf
        mode: "0644"
      notify: restart httpd

  handlers:
    - name: restart httpd
      ansible.builtin.service:
        name: httpd
        state: restarted
```

    The name after `notify` must match the handler's name exactly. The handler runs once, at the end of the play, however many tasks notify it.
    </Reveal>
  </Task>

  <Task title="A page built from facts">
    Create `templates/index.html.j2` and deploy it as `/var/www/html/index.html`, mode `0644`. The page on each host must show:

    - the host's fully qualified domain name, as a heading,
    - its default IPv4 address,
    - the inventory groups it belongs to, separated by commas.

    <Reveal title="Show solution">

```jinja title="templates/index.html.j2"
<h1>{{ ansible_facts['fqdn'] }}</h1>
<p>Address: {{ ansible_facts['default_ipv4']['address'] }}</p>
<p>Groups: {{ group_names | join(', ') }}</p>
```

```yaml
    - name: The page is built from facts
      ansible.builtin.template:
        src: templates/index.html.j2
        dest: /var/www/html/index.html
        mode: "0644"
```

    `group_names` is a magic variable, not a fact: it lists the groups of the current host, including parent groups such as `webservers`.
    </Reveal>
  </Task>

  <Task title="One user per environment">
    Create `vars/users.yml`:

```yaml title="vars/users.yml"
---
users:
  - name: ana
    env: dev
  - name: ben
    env: test
  - name: cara
    env: prod
```

    Add a second play for all hosts that creates each user only on the hosts of its environment: `ana` on the `dev` host, `ben` on `test`, `cara` on both `prod` hosts. Use one task.

    <Reveal title="Show solution">

```yaml
- name: Each environment has its own user
  hosts: all
  vars_files:
    - vars/users.yml
  tasks:
    - name: The user for this environment exists
      ansible.builtin.user:
        name: "{{ item['name'] }}"
        state: present
      loop: "{{ users }}"
      when: item['env'] in group_names
```

    The condition is tested for every item on every host, so each host keeps only the users of the groups it is in. Adding a user later means one more entry in the variables file and no change to the play.
    </Reveal>
  </Task>

  <Task title="Check the pages from the control node">
    Add a third play that runs on `localhost`, without privilege escalation and without gathering facts. It must request `http://HOST` for every host in `webservers`, and fail if the page does not contain that host's name.

    <Reveal title="Show solution">

```yaml
- name: The pages answer
  hosts: localhost
  become: false
  gather_facts: false
  tasks:
    - name: Every web server returns its own page
      ansible.builtin.uri:
        url: "http://{{ item }}"
        return_content: true
      register: page
      failed_when: item not in page.content
      loop: "{{ groups['webservers'] }}"
```

    `groups['webservers']` is the list of host names in the group, so the loop needs no hard-coded names. `become: false` matters here: the configuration turns privilege escalation on for every play, and there is no reason to use sudo on workstation to fetch a web page. Inside a loop, `register` and `failed_when` apply to each item in turn.
    </Reveal>
  </Task>
