  <Task title="Configure the project">
    In `~/review-deploy`, create `ansible.cfg` so that Ansible:

    - uses the inventory file `./inventory`,
    - connects as the user `devops`,
    - becomes `root` with `sudo` for every task, without asking for a password.

    <Reveal title="Show solution">

```ini title="ansible.cfg"
[defaults]
inventory = ./inventory
remote_user = devops
interpreter_python = auto_silent

[privilege_escalation]
become = true
become_method = sudo
become_user = root
become_ask_pass = false
```

    `interpreter_python = auto_silent` only hides the warning about the Python interpreter Ansible discovers on each host.
    </Reveal>
  </Task>

  <Task title="Write the inventory">
    Create `inventory` with these groups:

    | Group | Members |
    | --- | --- |
    | `dev` | servera.lab.example.com |
    | `test` | serverb.lab.example.com |
    | `prod` | serverc.lab.example.com, serverd.lab.example.com |
    | `webservers` | every host in `prod`, as a child group |

    <Reveal title="Show solution">

```ini title="inventory"
[dev]
servera.lab.example.com

[test]
serverb.lab.example.com

[prod]
serverc.lab.example.com
serverd.lab.example.com

[webservers:children]
prod
```
    </Reveal>
  </Task>

  <Task title="Configure a repository with ad hoc commands">
    Write an executable shell script `adhoc.sh` that runs two ad hoc commands against all hosts:

    1. Trust the signing key `/etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9`.
    2. Define a repository named `lab-crb`, described as `Rocky Linux 9 CRB (lab)`, from the mirror list `https://mirrors.rockylinux.org/mirrorlist?arch=$basearch&repo=CRB-$releasever`, with GPG checking on, using the key above, and enabled.

    The script must be safe to run again.

    <Env>
      <Classroom>
        Use the repository URL and key your classroom provides; the modules and options are the same.
      </Classroom>
      <HomeLab>
        Use the values above.
      </HomeLab>
    </Env>

    <Reveal title="Show solution">

```bash title="adhoc.sh"
#!/bin/bash
# Configure the lab-crb repository on every managed host with ad hoc commands.
ansible all -m ansible.builtin.rpm_key -a "key=/etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9 state=present"
ansible all -m ansible.builtin.yum_repository -a "name=lab-crb description='Rocky Linux 9 CRB (lab)' mirrorlist='https://mirrors.rockylinux.org/mirrorlist?arch=\$basearch&repo=CRB-\$releasever' gpgcheck=yes gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9 enabled=yes state=present"
```

```console
[student@workstation review-deploy]$ chmod +x adhoc.sh
```

    Two details decide whether this works. The argument string is in double quotes so the shell passes it as one piece, which means each `$` of a dnf variable must be escaped as `\$`. Values that contain spaces or `&` are wrapped in single quotes inside it.
    </Reveal>
  </Task>

  <Task title="Run it twice">

```console
[student@workstation review-deploy]$ ./adhoc.sh
serverb.lab.example.com | SUCCESS => {
servera.lab.example.com | SUCCESS => {
...output omitted...
servera.lab.example.com | CHANGED => {
serverc.lab.example.com | CHANGED => {
...output omitted...
[student@workstation review-deploy]$ ./adhoc.sh
...output omitted...
[student@workstation review-deploy]$ ansible all -m ansible.builtin.command -a 'dnf repolist' | grep -c lab-crb
4
```

    The key was already trusted, so the first command reports `SUCCESS`. The repository is new, so the second reports `CHANGED` on the first run and `SUCCESS` on the second. The count shows the repository enabled on all four hosts.
  </Task>

  <Task title="Protect a secret">
    Create the variables file `secret.yml`, encrypted with Ansible Vault using the password `redhat`, containing:

    - `dbadmin_password` with the value `Secret123`

    Save the vault password in `vault-pass`, readable only by you, so the playbook can run without prompting.

    <Reveal title="Show solution">

```console
[student@workstation review-deploy]$ echo redhat > vault-pass
[student@workstation review-deploy]$ chmod 600 vault-pass
[student@workstation review-deploy]$ ansible-vault create --vault-password-file vault-pass secret.yml
```

```yaml title="secret.yml (as typed in the editor)"
---
dbadmin_password: Secret123
```

```console
[student@workstation review-deploy]$ head -1 secret.yml
$ANSIBLE_VAULT;1.1;AES256
[student@workstation review-deploy]$ ansible-vault view --vault-password-file vault-pass secret.yml
---
dbadmin_password: Secret123
```

    Without `--vault-password-file`, both commands prompt for the password instead.
    </Reveal>
  </Task>

  <Task title="Use the secret">
    Write `dbadmin.yml` with one play for the `dev` group. It must load `secret.yml` and create the user `dbadmin` with `dbadmin_password` as the password, stored as a SHA-512 hash. A second run must not change anything.

    <Reveal title="Show solution">

```yaml title="dbadmin.yml"
---
- name: The database administrator exists on dev
  hosts: dev
  vars_files:
    - secret.yml
  tasks:
    - name: dbadmin exists with the vaulted password
      ansible.builtin.user:
        name: dbadmin
        password: "{{ dbadmin_password | password_hash('sha512', 'reviewsalt') }}"
        state: present
```

    The fixed salt makes the hash the same on every run, so the second run reports `ok`. Without it, `password_hash` picks a new salt each time and the task always reports `changed`. The other way to reach the same result is `update_password: on_create`.
    </Reveal>

```console
[student@workstation review-deploy]$ ansible-navigator run -m stdout dbadmin.yml --vault-password-file vault-pass
...output omitted...
servera.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
[student@workstation review-deploy]$ ansible-navigator run -m stdout dbadmin.yml --vault-password-file vault-pass
...output omitted...
servera.lab.example.com    : ok=2    changed=0    unreachable=0    failed=0  ...
```

    The play runs only on servera, the one host in `dev`.
  </Task>

  <Task title="Verify">

```console
[student@workstation review-deploy]$ ssh devops@servera 'sudo grep ^dbadmin /etc/shadow | cut -c1-24'
dbadmin:$6$reviewsalt$ay
[student@workstation review-deploy]$ ssh devops@serverb 'id dbadmin'
id: ‘dbadmin’: no such user
```

    `$6$` marks a SHA-512 hash, followed by the salt. The account exists on servera only.
  </Task>
