<Lead>
You will read serverb's network facts, add a second address on a new interface without touching the one Ansible uses, give it a name, and confirm from the facts that the change took effect.
</Lead>

The project `~/system-network` has an `ansible.cfg` and an `inventory` with serverb in `servers`.

<Lab
  id="network"
  title="Managing network configuration"
  classroom="lab start system-network"
  own
  hosts={['workstation', 'serverb.lab.example.com']}
  outcomes={['Read network facts.', 'Add a NetworkManager connection with nmcli, and a hosts entry.']}

  <Task title="Read the current configuration">

```console
[student@workstation ~]$ cd ~/system-network
[student@workstation system-network]$ ansible servers -m ansible.builtin.setup -a 'filter=ansible_default_ipv4'
serverb.lab.example.com | SUCCESS => {
    "ansible_facts": {
        "ansible_default_ipv4": {
            "address": "172.25.250.11",
            ...output omitted...
            "interface": "enp5s0",
            ...output omitted...
[student@workstation system-network]$ ssh devops@serverb 'nmcli -t -f NAME,TYPE,DEVICE con show'
System enp5s0:802-3-ethernet:enp5s0
lo:loopback:lo
```

    One real connection, `System enp5s0`, which is the one Ansible is using right now. Leave it alone.
  </Task>

  <Task title="Write the playbook">
    Create `network.yml` for `servers` that:

    1. prints the default interface and its address from the facts;
    2. adds a NetworkManager connection `lab-dummy0` of type `dummy` on interface `dummy0` with the address `192.0.2.10/24`, starting at boot;
    3. adds `192.0.2.10 internal.lab.example.com` to `/etc/hosts`;
    4. refreshes the network facts and prints dummy0's address from them.

    <Reveal title="Show network.yml">

```yaml title="network.yml"
---
- name: A second address for internal services
  hosts: servers
  tasks:
    - name: Show the current default interface
      ansible.builtin.debug:
        msg: "{{ ansible_facts['default_ipv4']['interface'] }} has {{ ansible_facts['default_ipv4']['address'] }}"

    - name: A dummy interface carries 192.0.2.10
      community.general.nmcli:
        conn_name: lab-dummy0
        type: dummy
        ifname: dummy0
        ip4: 192.0.2.10/24
        autoconnect: true
        state: present

    - name: The name is in /etc/hosts
      ansible.builtin.lineinfile:
        path: /etc/hosts
        line: 192.0.2.10 internal.lab.example.com
        state: present

    - name: Refresh facts
      ansible.builtin.setup:
        gather_subset: network

    - name: Show the new interface from facts
      ansible.builtin.debug:
        msg: "dummy0 has {{ ansible_facts['dummy0']['ipv4']['address'] }}"
```
    </Reveal>
  </Task>

  <Task title="Run it twice">

```console
[student@workstation system-network]$ ansible-navigator run -m stdout network.yml
...output omitted...
TASK [Show the current default interface] **************************************
ok: [serverb.lab.example.com] => {
    "msg": "enp5s0 has 172.25.250.11"
}
...output omitted...
TASK [Show the new interface from facts] ***************************************
ok: [serverb.lab.example.com] => {
    "msg": "dummy0 has 192.0.2.10"
}

PLAY RECAP *********************************************************************
serverb.lab.example.com    : ok=6    changed=2    unreachable=0    failed=0  ...
[student@workstation system-network]$ ansible-navigator run -m stdout network.yml
...output omitted...
serverb.lab.example.com    : ok=6    changed=0    unreachable=0    failed=0  ...
```

    The facts gathered at the start knew nothing about dummy0. The `setup` task refreshed them in the middle of the play.
  </Task>

  <Task title="Verify on the host">

```console
[student@workstation system-network]$ ssh devops@serverb 'nmcli -t -f NAME,TYPE,DEVICE con show; ip -4 -brief addr show dummy0; grep internal /etc/hosts'
System enp5s0:802-3-ethernet:enp5s0
lab-dummy0:dummy:dummy0
lo:loopback:lo
dummy0           UNKNOWN        192.0.2.10/24
192.0.2.10 internal.lab.example.com
[student@workstation system-network]$ ansible servers -m ansible.builtin.ping -o
serverb.lab.example.com | SUCCESS => {… "ping": "pong"}
```

    The new connection is there, and Ansible still reaches serverb through the untouched main interface.
  </Task>
