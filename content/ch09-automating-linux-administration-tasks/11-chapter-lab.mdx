<Lead>
Prepare serverc for an application team in one playbook: a group and an administrator with narrow sudo rights, its own logical volume mounted with the right ownership, the web server it needs, and a nightly job. Solutions are hidden under each task. Try each one yourself first.
</Lead>

The project `~/system-review` has an `ansible.cfg` and an `inventory` with serverc in the `app` group. Write everything in one playbook, `site.yml`, with one play for `app`.

  <Task title="The team and its administrator">
    Create the group `apps`, and the user `appadmin` as a member of it (keeping any other groups).

    <Reveal title="Show solution">

```yaml title="site.yml"
---
- name: The application server is prepared
  hosts: app
  tasks:
    - name: The apps group exists
      ansible.builtin.group:
        name: apps
        state: present

    - name: appadmin exists and is in apps
      ansible.builtin.user:
        name: appadmin
        groups: apps
        append: true
        state: present
```
    </Reveal>
  </Task>

  <Task title="Narrow sudo rights">
    Members of `apps` may run exactly one command as root without a password: `/usr/bin/systemctl restart httpd`. Put the rule in `/etc/sudoers.d/apps` and have it checked before it is installed.

    <Reveal title="Show solution">

```yaml
    - name: apps members may restart the application with sudo
      ansible.builtin.copy:
        content: "%apps ALL=(root) NOPASSWD: /usr/bin/systemctl restart httpd\n"
        dest: /etc/sudoers.d/apps
        mode: "0440"
        validate: /usr/sbin/visudo -cf %s
```
    </Reveal>
  </Task>

  <Task title="Storage for the application">
    On the spare disk: a 2 GiB LVM partition, the volume group `appvg`, a 1 GiB logical volume `applv` with ext4, mounted persistently on `/srv/app`. The mount point must be owned by `appadmin` and group `apps`, mode `2770`, so that new files belong to the group.

    <Reveal title="Show solution">

```yaml
    - name: The spare disk has a partition for LVM
      community.general.parted:
        device: /dev/sdb
        number: 1
        label: gpt
        part_end: 2GiB
        flags: [lvm]
        state: present

    - name: The volume group exists
      community.general.lvg:
        vg: appvg
        pvs: /dev/sdb1

    - name: The logical volume exists
      community.general.lvol:
        vg: appvg
        lv: applv
        size: 1g

    - name: It has an ext4 file system
      community.general.filesystem:
        dev: /dev/appvg/applv
        fstype: ext4

    - name: It is mounted on /srv/app
      ansible.posix.mount:
        path: /srv/app
        src: /dev/appvg/applv
        fstype: ext4
        state: mounted

    - name: appadmin owns /srv/app
      ansible.builtin.file:
        path: /srv/app
        owner: appadmin
        group: apps
        mode: "2770"
        state: directory
```

    The ownership task comes **after** the mount: set before it, it would apply to the empty directory underneath, hidden once the file system is mounted.
    </Reveal>
  </Task>

  <Task title="The web server">
    Install `httpd`, and make sure it is running and starts at boot.

    <Reveal title="Show solution">

```yaml
    - name: The web server is installed and running
      ansible.builtin.dnf:
        name: httpd
        state: present

    - name: httpd is started
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true
```
    </Reveal>
  </Task>

  <Task title="A nightly job">
    For `appadmin`, at 02:30 every night, archive `/srv/app` to `/tmp/app-DATE.tgz`, where `DATE` is today's date.

    <Reveal title="Show solution">

```yaml
    - name: A nightly archive job exists for appadmin
      ansible.builtin.cron:
        name: Archive app data
        user: appadmin
        hour: "2"
        minute: "30"
        job: tar czf /tmp/app-$(date +\%F).tgz -C /srv app
```

    In a crontab, `%` has a special meaning, so it is escaped as `\%`.
    </Reveal>
  </Task>
