<Lead>
You will give three developers accounts on serverb: a shared group, a password, key-based login, and sudo rights through a validated drop-in file. The list of people lives in a variables file, so the playbook itself never names anyone.
</Lead>

The project `~/system-users` has an `ansible.cfg`, an `inventory` with serverb in `servers`, and `vars/users.yml`:

```yaml title="vars/users.yml"
---
# The people who need accounts. All of them join the webdev group.
users:
  - name: jane
    comment: Jane Doe
  - name: omar
    comment: Omar Haddad
  - name: li
    comment: Li Wei
```

<Lab
  id="users"
  title="Managing users and authentication"
  classroom="lab start system-users"
  own
  hosts={['workstation', 'serverb.lab.example.com']}
  outcomes={['Create a group and users from a variables file.', 'Install SSH keys and a validated sudoers rule.']}
>
  <Task title="Create the group and the users">
    Create `users.yml`: one play for `servers` that loads `vars/users.yml`, defines `user_password: redhat`, creates the group `webdev`, and creates each user in it with a bash shell and that password. Set the password only when an account is created.

    <Reveal title="Show the start of users.yml">

```yaml title="users.yml"
---
- name: Web developers have accounts
  hosts: servers
  vars_files:
    - vars/users.yml
  vars:
    user_password: redhat          # in real life: in a Vault-encrypted file
  tasks:
    - name: The webdev group exists
      ansible.builtin.group:
        name: webdev
        state: present

    - name: Each user exists, in webdev
      ansible.builtin.user:
        name: "{{ item['name'] }}"
        comment: "{{ item['comment'] }}"
        groups: webdev
        append: true
        shell: /bin/bash
        password: "{{ user_password | password_hash('sha512', 'labsalt' ~ item['name']) }}"
        update_password: on_create
        state: present
      loop: "{{ users }}"
```

    The fixed salt (`labsalt` followed by the user name) keeps the hash the same on every run; `update_password: on_create` would be enough on its own.
    </Reveal>
  </Task>

  <Task title="Install student's key for each of them">
    Add a task that installs the public key `/home/student/.ssh/id_ed25519.pub` (on workstation) for every user.

    <Reveal title="Show the task">

```yaml
    - name: Each user can log in with student's key
      ansible.posix.authorized_key:
        user: "{{ item['name'] }}"
        key: "{{ lookup('ansible.builtin.file', '/home/student/.ssh/id_ed25519.pub') }}"
        state: present
      loop: "{{ users }}"
```

    In practice each person has their own key file in the project; one shared key keeps the exercise short.
    </Reveal>
  </Task>

  <Task title="Grant sudo through a drop-in file">
    Add a task that lets members of `webdev` run any command as root without a password, in `/etc/sudoers.d/webdev`, checked with `visudo` before it is installed.

    <Reveal title="Show the task">

```yaml
    - name: webdev members may run commands as root
      ansible.builtin.copy:
        content: "%webdev ALL=(ALL) NOPASSWD: ALL\n"
        dest: /etc/sudoers.d/webdev
        owner: root
        group: root
        mode: "0440"
        validate: /usr/sbin/visudo -cf %s
```
    </Reveal>
  </Task>

  <Task title="Run it twice">

```console
[student@workstation ~]$ cd ~/system-users
[student@workstation system-users]$ ansible-navigator run -m stdout users.yml
...output omitted...
serverb.lab.example.com    : ok=5    changed=4    unreachable=0    failed=0  ...
[student@workstation system-users]$ ansible-navigator run -m stdout users.yml
...output omitted...
serverb.lab.example.com    : ok=5    changed=0    unreachable=0    failed=0  ...
```

    `changed=0` the second time, including the password: that is the fixed salt at work.
  </Task>

  <Task title="Log in as a new user">

```console
[student@workstation system-users]$ ssh jane@serverb 'id; sudo -n id -un'
uid=1002(jane) gid=1003(jane) groups=1003(jane),1002(webdev) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
root
```

    The key worked, jane is in `webdev`, and `sudo -n` (never prompt) succeeded.
  </Task>

  <Task title="See the validation catch a mistake">
    Change the `content` line to something `visudo` rejects, for example `%webdev ALL=(ALL NOPASSWD: ALL` (a missing bracket), and run the playbook:

```text
fatal: [serverb.lab.example.com]: FAILED! => {… "msg": "failed to validate", …
"stderr": "…/source:1:18: syntax error\n%webdev ALL=(ALL NOPASSWD: ALL\n                 ^~~~~~~~~\n" …}
```

    The broken file never reached `/etc/sudoers.d/`, and `sudo` keeps working. Put the line back and run again.
  </Task>

## Try it again, differently

Add a fourth person to `vars/users.yml` and run again: only their account, key and group membership change. Then give `li` the extra field `state: absent` in the list and make the user task use `state: "{{ item['state'] | default('present') }}"` with `remove: true`, so the same loop can remove people too.
