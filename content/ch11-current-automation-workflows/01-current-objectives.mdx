<Lead>You can already write automation for the RHEL 9 home lab. This chapter helps you carry those skills into a project that someone else can clone, edit, run, and recover.</Lead>

## Know which environment you are using

There are two questions to answer before running a project: **where are my tools installed?** and **where will my playbook execute?** A host installation, an editor container, and an execution image can each contain different versions and collections.

The main home lab uses Rocky Linux 9 and ansible-core 2.14. Keep that working baseline for chapters 1–10. This bridge introduces another workflow without requiring you to upgrade the lab.

On workstation, record these commands' output in a short `environment-notes.md` file:

```bash
ansible --version
ansible-navigator --version
ansible-galaxy collection list
ansible-navigator settings --mode stdout
```

The first command identifies the engine and configuration path. The second identifies navigator. The collection list shows locally installed content. Navigator's settings tell you whether it will run locally or start an execution environment. **Local versions do not describe the contents of an execution image.**

## A habit that transfers

Keep playbooks, inventory, dependency requirements, and tool settings together. Save changes in Git, record the runtime you tested, and verify the resulting host. By the end of this chapter, you should be able to explain **what was run, where it ran, and how to reproduce the result**.
