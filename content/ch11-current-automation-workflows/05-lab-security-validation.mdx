<LabChallenge>

Provide narrowly scoped privileged access on servera using `access.yml`.

- Account `auditor` must exist and be allowed to run `/usr/bin/id` as root without a password, through `/etc/sudoers.d/auditor`.
- The policy must belong to root:root with mode `0440`. Invalid policy content must be rejected before replacing the installed file.
- Demonstrate the allowed command returns root's identity, then demonstrate an invalid replacement leaves the working policy intact.
- Restore the valid source and prove repeatability. Keep devops SSH and sudo access usable throughout.

</LabChallenge>

<Task id="task-e4230a35326c" legacyIndex={1} title="Define the result">
Work in `~/bridge-security`, which `lab start` prepares. Save `access.yml` with a play for `servera.lab.example.com` and privilege escalation.

The account `auditor` needs one privileged diagnostic operation: `/usr/bin/id`. It must not receive general administrator access. Keep devops, the connection account, unchanged so you can correct your work if a policy is rejected.

The desired result is a narrowly scoped sudo policy, installed only after a syntax check. You will prove both the permitted action and the protection against an invalid replacement.
</Task>
<Task id="task-38874ab662ff" legacyIndex={2} title="Deploy a validated policy">
Add an `ansible.builtin.user` task to ensure `auditor` exists. Then add an `ansible.builtin.copy` task for `/etc/sudoers.d/auditor`, owned by root:root with mode `0440`.

Its content should permit auditor to run the required command as root without a password. Read the hint if you need the sudoers rule syntax. Add `validate: /usr/sbin/visudo -cf %s` to the copy task.

`%s` is replaced with a temporary file path. Ansible asks `visudo` to check that file **before** replacing the destination. Root ownership and mode `0440` protect the installed policy from ordinary-user edits; validation protects it from malformed replacements.
<Reveal title="Hint: a narrowly scoped rule">
The file can contain `auditor ALL=(root) NOPASSWD: /usr/bin/id`. Validation checks the temporary file before Ansible replaces the destination.
</Reveal>
</Task>
<Task id="task-ef043f5acd2d" legacyIndex={3} title="Verify the policy and connection">
From workstation, check syntax, run the play, and inspect the resulting policy and behavior:

```bash
ansible-playbook access.yml --syntax-check
ansible-playbook access.yml
ssh devops@servera.lab.example.com 'sudo visudo -c'
ssh devops@servera.lab.example.com 'sudo -u auditor sudo -n /usr/bin/id'
ansible servera.lab.example.com -m ansible.builtin.ping
lab grade bridge-security
```

`visudo` should report the policy files parsed successfully. The identity command should print `uid=0(root)`: its inner sudo runs as auditor and requests no interactive password. The Ansible ping proves devops still connects and executes a module.

Repeat the playbook and expect no configuration changes. Checking syntax alone would miss an overly broad rule or an unusable account, so inspect both the policy and the command result.
</Task>
<Task id="task-c8141a8b7639" legacyIndex={4} title="Test a rejected change">
In the **playbook source**, temporarily replace the rule with `auditor ALL=(root` (an incomplete rule). Rerun `access.yml`. The copy task should fail its validation, and the previously installed valid policy should remain intact.

Read the installed file with `ssh devops@servera.lab.example.com 'sudo cat /etc/sudoers.d/auditor'` and repeat the allowed identity command. Both should still reflect the working policy. This demonstrates rejection before replacement.

Restore the valid content in your playbook, run it again, and grade the restored state. Avoid editing the live sudoers file to introduce this fault: doing so would bypass the validation mechanism you are practising.
</Task>
</Lab>

<Reveal title="One working solution">

```yaml title="access.yml"
- name: Configure a limited audit account
  hosts: servera.lab.example.com
  become: true
  tasks:
    - name: Create the account
      ansible.builtin.user:
        name: auditor
        state: present
    - name: Install a validated sudo policy
      ansible.builtin.copy:
        content: "auditor ALL=(root) NOPASSWD: /usr/bin/id\n"
        dest: /etc/sudoers.d/auditor
        owner: root
        group: root
        mode: '0440'
        validate: /usr/sbin/visudo -cf %s
```

</Reveal>

## Recap

Restrict the allowed operation, protect the policy's permissions, validate before replacement, and verify actual access. A deliberately rejected source change should leave the last valid installed policy usable.
