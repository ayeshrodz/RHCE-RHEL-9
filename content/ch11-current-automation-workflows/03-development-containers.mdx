<Lead>A development container gives your editor consistent tools. An execution environment gives a playbook consistent runtime dependencies. Learn to identify both.</Lead>

## Prepare a project

Install VS Code, its Dev Containers extension, and the Ansible extension on a machine with Podman or Docker. The workstation lab is terminal based; this editor exercise belongs on a machine with a desktop. It can use the same playbook project through Git.

In your project, create:

```json title=".devcontainer/devcontainer.json"
{
  "name": "Ansible practice",
  "image": "ghcr.io/ansible/community-ansible-dev-tools:latest",
  "customizations": {
    "vscode": {
      "extensions": ["redhat.ansible"]
    }
  }
}
```

Use **Dev Containers: Reopen in Container**. The public community image does not require a Red Hat registry account. `latest` can change: after a successful pull, record its digest with your container engine and use that digest in the configuration for repeatable attempts.

## Prove where the tools run

In the container terminal:

```bash
ansible --version
ansible-navigator --version
ansible-lint --version
ansible-playbook hello.yml --syntax-check
ansible-playbook hello.yml
```

Use the localhost playbook from the Git lesson first. Remote labs additionally need their network and SSH access available from the container. A desktop outside the sealed lab cannot directly SSH into its managed hosts; practise the container tools locally or run navigator on workstation for those exercises.

## Configure navigator deliberately

For a localhost exercise inside the development container, use its installed tools:

```yaml title="ansible-navigator.yml"
ansible-navigator:
  mode: stdout
  execution-environment:
    enabled: false
  playbook-artifact:
    enable: false
```

```bash
ansible-navigator run hello.yml
ansible-navigator doc ansible.builtin.copy --mode stdout
```

To practise a separate execution environment on workstation, select an image explicitly:

```bash
ansible-navigator run hello.yml --ee true \
  --execution-environment-image ghcr.io/ansible-community/community-ee-minimal:latest \
  --mode stdout
```

A minimal image may omit collections needed by later labs. Inspect its contents and install dependencies when building your own image; a host-installed collection does not cross the container boundary automatically.

## When newer templates behave differently

Core 2.19 introduced stricter templating and conditional checks. Use actual booleans for conditions, keep `{{ }}` out of `when`, and do not assume text from a command is a trusted template. Reproduce an error with the smallest playbook before changing a whole project.
