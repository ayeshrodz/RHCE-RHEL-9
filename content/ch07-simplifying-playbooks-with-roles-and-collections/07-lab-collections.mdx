<Lead>
You will write a task that uses a module from a collection you do not have yet, meet both of the common errors on the way, and finish with a project that records exactly which collection version it needs.
</Lead>

The project `~/collection-use` has an `inventory` that lists `servera`, and an `ansible.cfg` whose `collections_path` puts the project's own `./collections` directory first.

<Lab
  id="collections"
  title="Getting modules from a collection"
  classroom="lab start collection-use"
  own
  hosts={['workstation', 'servera.lab.example.com']}
  outcomes={[
    'Install a pinned collection into a project from a requirements file.',
    'Tell a missing collection from a missing Python library, and fix both.',
  ]}
>
  <HomeSetup>
    This exercise downloads one collection from the public Ansible Galaxy site, which the lab reaches through NAT.
  </HomeSetup>

  <Task title="See what is installed">

```console
[student@workstation ~]$ cd ~/collection-use
[student@workstation collection-use]$ grep collections_path ansible.cfg
collections_path = ./collections:~/.ansible/collections:/usr/share/ansible/collections
[student@workstation collection-use]$ ansible-galaxy collection list

# /usr/share/ansible/collections/ansible_collections
Collection               Version
------------------------ -------
ansible.posix            1.5.4
community.general        9.5.13
redhat.rhel_system_roles 1.120.5
```

    There is no `community.crypto`.
  </Task>

  <Task title="Write a playbook that needs it">
    Create `key.yml`. Its task makes sure a 2048-bit private key exists on servera.

```yaml title="key.yml"
---
- name: A private key exists
  hosts: all
  tasks:
    - name: The private key exists
      community.crypto.openssl_privatekey:
        path: /etc/pki/tls/private/lab.key
        size: 2048
        mode: "0600"
```
  </Task>

  <Task title="Meet the first error">

```console
[student@workstation collection-use]$ ansible-navigator run -m stdout key.yml
ERROR! couldn't resolve module/action 'community.crypto.openssl_privatekey'. This often indicates a misspelling, missing collection, or incorrect module path.
...output omitted...
```

    No play started and no host was contacted. The control node does not have the module.
  </Task>

  <Task title="Record and install the collection">
    Create `collections/requirements.yml` with the collection and the version this project uses, then install from it.

```yaml title="collections/requirements.yml"
---
collections:
  - name: community.crypto
    version: 2.26.0
```

```console
[student@workstation collection-use]$ ansible-galaxy collection install -r collections/requirements.yml -p collections
...output omitted...
Installing 'community.crypto:2.26.0' to '/home/student/collection-use/collections/ansible_collections/community/crypto'
community.crypto:2.26.0 was installed successfully
[student@workstation collection-use]$ ansible-galaxy collection list | grep -B3 crypto

# /home/student/collection-use/collections/ansible_collections
Collection       Version
---------------- -------
community.crypto 2.26.0
```

    <Callout type="note" title="Why 2.26.0 and not the newest?">
    The 2.x series of this collection supports the `ansible-core` 2.14 that RHEL 9 ships. Its 3.x series needs a newer `ansible-core`.
    </Callout>
  </Task>

  <Task title="Read the module's requirements">

```console
[student@workstation collection-use]$ ansible-navigator doc community.crypto.openssl_privatekey -m stdout | grep -A1 REQUIREMENTS
REQUIREMENTS:  cryptography >= 1.2.3 (older versions might work as
        well)
```

    The module needs the Python `cryptography` library **on the host that executes it**, which is the managed host. Read the whole page without the `grep` too: the options and the examples at the end are what you will use most.
  </Task>

  <Task title="Meet the second error">

```console
[student@workstation collection-use]$ ansible-navigator run -m stdout key.yml
...output omitted...
TASK [The private key exists] **************************************************
fatal: [servera.lab.example.com]: FAILED! => {"changed": false, "msg": "Cannot detect the required Python library cryptography (>= 1.2.3)"}
```

    This time the play ran and one task failed on servera. The collection is fine; the managed host lacks a library.
  </Task>

  <Task title="Install the library first">
    Add a task **before** the key task that installs `python3-cryptography`.

    <Reveal title="Show the complete key.yml">

```yaml title="key.yml"
---
- name: A private key exists
  hosts: all
  tasks:
    - name: The cryptography library is installed
      ansible.builtin.dnf:
        name: python3-cryptography
        state: present

    - name: The private key exists
      community.crypto.openssl_privatekey:
        path: /etc/pki/tls/private/lab.key
        size: 2048
        mode: "0600"
```
    </Reveal>
  </Task>

  <Task title="Run, verify and run again">

```console
[student@workstation collection-use]$ ansible-navigator run -m stdout key.yml
...output omitted...
servera.lab.example.com    : ok=3    changed=2    unreachable=0    failed=0  ...
[student@workstation collection-use]$ ssh devops@servera 'sudo ls -l /etc/pki/tls/private/lab.key; sudo openssl rsa -in /etc/pki/tls/private/lab.key -check -noout'
-rw-------. 1 root root 1675 ... /etc/pki/tls/private/lab.key
RSA key ok
[student@workstation collection-use]$ ansible-navigator run -m stdout key.yml
...output omitted...
servera.lab.example.com    : ok=3    changed=0    unreachable=0    failed=0  ...
```

    The second run changes nothing: the module sees a valid key of the right size and leaves it alone.
  </Task>

    <Env>

      </HomeLab>
    </Env>
  </Task>
</Lab>

## Try it again, differently

Delete the `collections/ansible_collections` directory and restore it with the one `ansible-galaxy` command. That is all a colleague needs to do after cloning your project: the requirements file is the record, the downloaded collection is disposable.
