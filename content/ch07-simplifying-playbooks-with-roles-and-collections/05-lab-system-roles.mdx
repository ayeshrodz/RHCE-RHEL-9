<Lead>
You will give two servers a baseline using roles you did not write: a system role that configures time synchronisation, and a small role that you install from an archive with a requirements file.
</Lead>

The project `~/role-system` has an `ansible.cfg`, an `inventory` with a `servers` group (`servera` and `serverb`), and `archives/acme.banner-1.0.tar.gz`, a packaged role that writes a login banner.

<Lab
  id="sysroles"
  title="System roles and installed roles"
  classroom="lab start role-system"
  own
  hosts={['workstation', 'servera.lab.example.com', 'serverb.lab.example.com']}
  outcomes={[
    'Find a system role and read its documentation.',
    'Install a role from an archive with a requirements file.',
    'Apply both roles in one play.',
  ]}
>
  <HomeSetup>
    `lab start` builds the role archive on your workstation, so there is no download. The time servers used below are public NTP pool servers, which the lab reaches through NAT.
  </HomeSetup>

  <Task title="Find the system role">
    Confirm the system roles are installed, in both forms, and look at what the `timesync` role documents.

```console
[student@workstation ~]$ cd ~/role-system
[student@workstation role-system]$ ansible-galaxy collection list | grep rhel_system_roles
redhat.rhel_system_roles 1.120.5
[student@workstation role-system]$ ls /usr/share/ansible/roles | grep timesync
linux-system-roles.timesync
rhel-system-roles.timesync
[student@workstation role-system]$ ls /usr/share/doc/rhel-system-roles/timesync/
CHANGELOG.md  example-multiple-ntp-servers-playbook.yml  example-single-pool-playbook.yml  README.html  README.md
```

    Open `example-single-pool-playbook.yml`: it shows the variable this exercise uses.
  </Task>

  <Task title="Look inside the archive">
    Never install a role blind. List what is in it:

```console
[student@workstation role-system]$ tar tzf archives/acme.banner-1.0.tar.gz
acme.banner/
acme.banner/tasks/
acme.banner/tasks/main.yml
acme.banner/defaults/
acme.banner/defaults/main.yml
acme.banner/meta/
acme.banner/meta/main.yml
```

    Three files: tasks, defaults and meta. A small role.
  </Task>

  <Task title="Write the requirements file">
    Create `roles/requirements.yml` that installs the archive under the name `acme.banner`.

    <Reveal title="Show roles/requirements.yml">

```yaml title="roles/requirements.yml"
---
- src: file:///home/student/role-system/archives/acme.banner-1.0.tar.gz
  name: acme.banner
```
    </Reveal>
  </Task>

  <Task title="Install the role">

```console
[student@workstation role-system]$ ansible-galaxy role install -r roles/requirements.yml -p roles
Starting galaxy role install process
- downloading role from file:///home/student/role-system/archives/acme.banner-1.0.tar.gz
- extracting acme.banner to /home/student/role-system/roles/acme.banner
- acme.banner was installed successfully
[student@workstation role-system]$ ansible-galaxy role list -p roles
# /home/student/role-system/roles
- acme.banner, (unknown version)
...output omitted...
```

    Now read what you installed: `cat roles/acme.banner/defaults/main.yml roles/acme.banner/tasks/main.yml`. Its one variable is `banner_text`.
  </Task>

  <Task title="Write the play">
    Create `site.yml`. One play for the `servers` group, using both roles, with their variables set in the play.

    <Env>
      <Classroom>
        A classroom usually has no internet access. Use the NTP server your classroom provides as the `hostname`, without `pool: true`.
      </Classroom>
      <HomeLab>
        Use a public NTP pool:

```yaml title="site.yml"
---
- name: Servers have a baseline
  hosts: servers
  vars:
    timesync_ntp_servers:
      - hostname: 0.rocky.pool.ntp.org
        pool: true
        iburst: true
    banner_text: Authorised users only.
  roles:
    - redhat.rhel_system_roles.timesync
    - acme.banner
```
      </HomeLab>
    </Env>
  </Task>

  </Task>

    `changed=0`, and one task fewer: the handler had nothing to do.
  </Task>

  <Task title="Finish">
    <Env>
      <Classroom>
        This exercise is not part of a course, so there is no `lab finish` for it. Reset or clean the two servers the way your classroom provides before the next exercise.
      </Classroom>
      <HomeLab>
        Two steps. On workstation, `lab finish role-system` moves your project to `~/lab-archive/`. Then, on the Ubuntu host, `rht-vmctl reset servers` puts every managed host back to the clean baseline.
      </HomeLab>
    </Env>
  </Task>
</Lab>

## Try it again, differently

Add the `redhat.rhel_system_roles.selinux` role to the play and use it to switch on the boolean `httpd_can_network_connect` persistently. Its README in `/usr/share/doc/rhel-system-roles/selinux/` shows the variable to set. Verify with `ssh devops@servera getsebool httpd_can_network_connect`.
