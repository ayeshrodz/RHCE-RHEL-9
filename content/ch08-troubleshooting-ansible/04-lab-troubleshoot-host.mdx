<Lead>
This time the playbook is correct. Three things around it are not: two hosts have bad connection settings in the inventory, and privilege escalation is switched off. You will find each with Ansible's own tools, preview the change with check mode, then apply it.
</Lead>

The project `~/troubleshoot-host` has an `ansible.cfg`, an `inventory` with a `web` group of three servers, a playbook `motd.yml` that deploys a message of the day from `templates/motd.j2`, and no mistakes in the playbook itself.

<Lab
  id="tshost"
  title="Troubleshooting managed hosts"
  classroom="lab start troubleshoot-host"
  own
  hosts={['workstation', 'servera.lab.example.com', 'serverb.lab.example.com', 'serverc.lab.example.com']}
  outcomes={[
    'Find why a host is unreachable from the message, the inventory and -vvv.',
    'Tell a privilege problem from a connection problem.',
    'Preview a change with check mode and a diff before applying it.',
  ]}
>
  <Task title="Test the connections">

```console
[student@workstation ~]$ cd ~/troubleshoot-host
[student@workstation troubleshoot-host]$ ansible web -m ansible.builtin.ping
serverc.lab.example.com | UNREACHABLE! => {
    "changed": false,
    "msg": "Failed to connect to the host via ssh: operator1@serverc.lab.example.com: Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password).",
    "unreachable": true
}
servera.lab.example.com | SUCCESS => {
    ...output omitted...
    "ping": "pong"
}
serverb.lab.example.com | UNREACHABLE! => {
    "changed": false,
    "msg": "Failed to connect to the host via ssh: ssh: connect to host 172.25.250.211 port 22: No route to host",
    "unreachable": true
}
```

    One works and two do not, for different reasons. serverb is being contacted at an address that does not answer; serverc answers, but refuses the user `operator1`.
  </Task>

  <Task title="Ask Ansible where those settings come from">

```console
[student@workstation troubleshoot-host]$ ansible-navigator inventory -m stdout --host serverb.lab.example.com
{
    "ansible_host": "172.25.250.211"
}
[student@workstation troubleshoot-host]$ ansible-navigator inventory -m stdout --host serverc.lab.example.com
{
    "ansible_user": "operator1"
}
[student@workstation troubleshoot-host]$ getent hosts serverb.lab.example.com
172.25.250.11   serverb.lab.example.com
```

    Both hosts have a variable that overrides the normal settings. The name `serverb.lab.example.com` resolves to `.11`, but `ansible_host` sends Ansible to `.211`.

    For serverc, `-vvv` shows the same thing from the connection's side:

```console
[student@workstation troubleshoot-host]$ ansible serverc.lab.example.com -m ansible.builtin.ping -vvv
...output omitted...
<serverc.lab.example.com> ESTABLISH SSH CONNECTION FOR USER: operator1
...output omitted...
```
  </Task>

  <Task title="Fix the inventory">
    Remove the two overrides, so both hosts use their names and the `remote_user` from `ansible.cfg`.

    <Reveal title="Show the fixed inventory">

```ini title="inventory"
[web]
servera.lab.example.com
serverb.lab.example.com
serverc.lab.example.com
```
    </Reveal>

```console
[student@workstation troubleshoot-host]$ ansible web -m ansible.builtin.ping -o
servera.lab.example.com | SUCCESS => {… "ping": "pong"}
serverc.lab.example.com | SUCCESS => {… "ping": "pong"}
serverb.lab.example.com | SUCCESS => {… "ping": "pong"}
```
  </Task>

  <Task title="Preview the change">
    Everything connects. Before changing three servers, preview with check mode:

```console
[student@workstation troubleshoot-host]$ ansible-navigator run -m stdout motd.yml --check
...output omitted...
servera.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
serverb.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
serverc.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
```

    It looks fine. Remember this result for the next task.
  </Task>

  <Task title="Run it for real">

```console
[student@workstation troubleshoot-host]$ ansible-navigator run -m stdout motd.yml
...output omitted...
TASK [Message of the day is in place] ******************************************
fatal: [servera.lab.example.com]: FAILED! => {… "changed": false, "checksum": "…", "msg": "Destination /etc not writable"}
...output omitted...
PLAY RECAP *********************************************************************
servera.lab.example.com    : ok=1    changed=0    unreachable=0    failed=1  ...
serverb.lab.example.com    : ok=1    changed=0    unreachable=0    failed=1  ...
serverc.lab.example.com    : ok=1    changed=0    unreachable=0    failed=1  ...
```

    `FAILED`, not `UNREACHABLE`: Ansible connected and gathered facts, then could not write to `/etc` as `devops`. Check mode could not see this, because it never attempted the write.

    <Reveal title="Show the cause and the fix">

```console
[student@workstation troubleshoot-host]$ grep become ansible.cfg
become = false
become_method = sudo
become_user = root
become_ask_pass = false
```

    Set `become = true` in `ansible.cfg` (or `become: true` in the play).
    </Reveal>
  </Task>

  <Task title="Preview with a diff, then apply">

```console
[student@workstation troubleshoot-host]$ ansible-navigator run -m stdout motd.yml --check --diff
...output omitted...
TASK [Message of the day is in place] ******************************************
--- before: /etc/motd
+++ after: /home/student/.ansible/tmp/…/motd.j2
@@ -0,0 +1,2 @@
+This is serverb.lab.example.com.
+Contact: ops@example.com

changed: [serverb.lab.example.com]
...output omitted...
[student@workstation troubleshoot-host]$ ansible-navigator run -m stdout motd.yml
...output omitted...
servera.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
serverb.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
serverc.lab.example.com    : ok=2    changed=1    unreachable=0    failed=0  ...
```

    The diff shows each host's own file before anything is written. `/etc/motd` was empty, so every line is new (`+`).
  </Task>

  <Task title="Verify">

```console
[student@workstation troubleshoot-host]$ ansible-navigator run -m stdout motd.yml
...output omitted...
servera.lab.example.com    : ok=2    changed=0    unreachable=0    failed=0  ...
serverb.lab.example.com    : ok=2    changed=0    unreachable=0    failed=0  ...
serverc.lab.example.com    : ok=2    changed=0    unreachable=0    failed=0  ...
[student@workstation troubleshoot-host]$ ssh devops@serverc cat /etc/motd
This is serverc.lab.example.com.
Contact: ops@example.com
```
  </Task>
