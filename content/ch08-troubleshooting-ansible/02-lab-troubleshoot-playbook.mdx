<Lead>
The playbook in this exercise has five mistakes, one of each common kind. You will find them the way you would at work: run, read the message, decide at which stage it failed, fix, and run again. The last one is the kind Ansible cannot see at all.
</Lead>

The project `~/troubleshoot-playbook` has an `ansible.cfg`, an `inventory` with servera in the `web` group, and `site.yml`: one play that should publish a web page on servera, and a second play that checks the page from workstation. Do not fix anything until a message leads you to it.

<Lab
  id="tsplaybook"
  title="Troubleshooting a playbook"
  classroom="lab start troubleshoot-playbook"
  own
  hosts={['workstation', 'servera.lab.example.com']}
  outcomes={[
    'Find and fix YAML, indentation, variable and argument errors from their messages.',
    'Rerun from a failed task, and find a problem that Ansible cannot detect.',
  ]}
>
  <Task title="Check the syntax">

```console
[student@workstation ~]$ cd ~/troubleshoot-playbook
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml --syntax-check
[WARNING]: While constructing a mapping from /home/student/troubleshoot-
playbook/site.yml, line 26, column 7, found a duplicate dict key (name). Using
last defined value only.
ERROR! We were unable to read either as JSON nor YAML, these are the errors we got from each:
JSON: Expecting value: line 1 column 1 (char 0)

Syntax Error while loading YAML.
  found unacceptable key (unhashable type: 'AnsibleMapping')

The error appears to be in '/home/student/troubleshoot-playbook/site.yml': line 11, column 16, but may
be elsewhere in the file depending on the exact syntax problem.

The offending line appears to be:

      ansible.builtin.dnf:
        name: {{ web_package }}
               ^ here
...output omitted...
```

    Two problems are reported. Deal with the `ERROR!` first. It points at line 11, a value that starts with `{{` without quotes, and the end of the message even suggests the fix.

    <Reveal title="Show the fix">

```yaml
        name: "{{ web_package }}"
```
    </Reveal>

    Keep the `[WARNING]` in mind: a duplicate key `name` at line 26. It is the next problem.
  </Task>

  <Task title="Check the syntax again">

```console
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml --syntax-check
...output omitted...
ERROR! conflicting action statements: ansible.builtin.service, state

The error appears to be in '/home/student/troubleshoot-playbook/site.yml': line 26, column 7, but may
be elsewhere in the file depending on the exact syntax problem.

The offending line appears to be:

    - name: Web service is running
      ^ here
```

    Look at the whole task at line 26. Its arguments are at the same level as `ansible.builtin.service:`, so Ansible reads `state` as a second module, and `name` twice, which explains the earlier warning.

    <Reveal title="Show the fix">

```yaml
    - name: Web service is running
      ansible.builtin.service:
        name: "{{ web_srv }}"
        state: start
        enabled: true
```
    </Reveal>

    Run `--syntax-check` once more: it now prints only the playbook name. The file can be read; what remains only shows up when tasks run.
  </Task>

  <Task title="Run the playbook">

```console
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml
...output omitted...
TASK [Web service is running] **************************************************
fatal: [servera.lab.example.com]: FAILED! => {"msg": "The task includes an option with an undefined variable. The error was: 'web_srv' is undefined. 'web_srv' is undefined …"}

PLAY RECAP *********************************************************************
servera.lab.example.com    : ok=4    changed=3    unreachable=0    failed=1  ...
```

    Three tasks made changes before this one failed. The variable `web_srv` is not defined; compare with the `vars` section at the top of the play.

    <Reveal title="Show the fix">

    The play defines `web_service`. Use that name: `name: "{{ web_service }}"`.
    </Reveal>
  </Task>

  <Task title="Rerun from the failed task">
    The first three tasks already worked. Start at the one that failed:

```console
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml \
> --start-at-task "Web service is running"
...output omitted...
TASK [Web service is running] **************************************************
fatal: [servera.lab.example.com]: FAILED! => {"changed": false, "msg": "value of state must be one of: reloaded, restarted, started, stopped, got: start"}
```

    The variable is fixed; now the module rejects a value, and the message lists the accepted ones.

    <Reveal title="Show the fix">

```yaml
        state: started
```
    </Reveal>
  </Task>

  <Task title="Run everything again">

```console
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml
...output omitted...
TASK [Home page returns our text] **********************************************
fatal: [localhost]: FAILED! => {… "content": "<!doctype html>\n<html>\n  <head>\n … <title>HTTP Server Test Page …", … "failed_when_result": true, … "status": 403, …}

PLAY RECAP *********************************************************************
localhost                  : ok=0    changed=0    unreachable=0    failed=1  ...
servera.lab.example.com    : ok=5    changed=1    unreachable=0    failed=0  ...
```

    Every task on servera succeeded, and yet the check fails. The web server answered with **403** and its test page, not our text. Ansible did exactly what the playbook says; the playbook says the wrong thing.
  </Task>

  <Task title="Investigate the host">
    Look at what the server returns, and where the page actually went:

```console
[student@workstation troubleshoot-playbook]$ curl -s -o /dev/null -w '%{http_code}\n' http://servera.lab.example.com
403
[student@workstation troubleshoot-playbook]$ ssh devops@servera 'ls -l /var/www/index.html /var/www/html/'
-rw-r--r--. 1 root root 20 … /var/www/index.html

/var/www/html/:
total 0
```

    <Reveal title="Show the cause and the fix">

    The page was written to `/var/www/index.html`, but Apache serves `/var/www/html`, which is empty. With no index page it shows its test page with status 403. Fix the variable:

```yaml
    web_root: /var/www/html
```
    </Reveal>
  </Task>

  <Task title="Confirm, and confirm again">

```console
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml
...output omitted...
localhost                  : ok=1    changed=0    unreachable=0    failed=0  ...
servera.lab.example.com    : ok=5    changed=1    unreachable=0    failed=0  ...
[student@workstation troubleshoot-playbook]$ ansible-navigator run -m stdout site.yml
...output omitted...
localhost                  : ok=1    changed=0    unreachable=0    failed=0  ...
servera.lab.example.com    : ok=5    changed=0    unreachable=0    failed=0  ...
```

    The test passes, and the second run changes nothing. The stray `/var/www/index.html` is harmless; delete it with an ad hoc `file` command if you like.
  </Task>

  </Task>

## What you practised

| Mistake | Found by | Stage |
| --- | --- | --- |
| Unquoted `{{ }}` at the start of a value | `--syntax-check` | Read |
| Arguments not indented under the module | `--syntax-check` | Read |
| Misspelt variable name | Running the play | Task |
| Value the module does not accept | Running from that task | Task |
| Page written to the wrong directory | A test play, then `curl` and `ssh` | Result |
